# AI INSTRUCTIONS & PROJECT CONTEXT: SPORTA WEB-OWNER

## 1. Project Overview
You are acting as a Senior React Developer and Mobile Hybrid Expert.
This module (`web-owner`) is the Facility Owner Portal for "Sporta", a sports facility booking and matchmaking platform. 

## 2. Hybrid Architecture (Crucial Context)
- **The Concept:** This is a Hybrid application. It runs as a fully responsive Web App on desktop browsers AND is wrapped as a native mobile app using **CapacitorJS**. 
- **The Mobile Strategy:** The native mobile app simply loads the URL of this web app into a WebView. Therefore, 100% of the UI must be built with web technologies but must feel like a native app on mobile screens (touch-friendly, no horizontal scrolling issues, safe-area padded).
- **Hardware Access:** When the user needs to use native features (specifically the Camera to scan Entry QR Codes), we use Capacitor plugins (`@capacitor/camera` or `@capacitor/barcode-scanner`), NOT standard web HTML5 camera APIs.

## 3. Tech Stack
- **Framework:** React.js (Functional Components, Hooks).
- **Build Tool:** Vite (SWC).
- **Language:** TypeScript (Strict mode).
- **Styling:** Tailwind CSS **v4** (Do NOT use `tailwind.config.js` or v3 syntax. Use the new `@import "tailwindcss";` syntax).
- **State Management:** Zustand (for global state) and TanStack Query (for API caching/syncing).
- **Hybrid Wrapper:** CapacitorJS.

## 4. Key Business Modules for this App
1. **Dashboard & Analytics:** View daily revenue, pending bookings, and available slots.
2. **Booking Matrix (Gantt Chart):** A complex UI showing time slots (columns) and sub-facilities (rows). Needs to handle real-time locking states (Optimistic UI).
3. **QR Code Scanner:** A dedicated screen to scan a customer's booking QR code, validate it with the backend, and mark the status as "Checked-in".
4. **Facility Management:** Forms to update facility details, upload images, and set dynamic pricing rules.

## 5. Strict Coding Guidelines for AI
- **Mobile-First CSS:** Always write Tailwind classes for mobile first, then scale up using `md:` and `lg:` prefixes for the desktop dashboard.
- **Component Structure:** Keep components small. Separate business logic (Custom Hooks) from the UI components.
- **Type Safety:** Always define precise TypeScript Interfaces/Types for API responses and component props. Avoid `any`.
- **Tailwind v4:** Remember that Tailwind v4 does not need arbitrary values as much; leverage its modern CSS variables approach.
- **No Hallucinations:** If you are unsure about the Capacitor API version, ask me to provide the documentation rather than guessing legacy Cordova plugins.
