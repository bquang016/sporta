Xung đột trạng thái Bảo trì và Lịch đặt (Lỗi UI ảo)Đây là lỗi nghiêm trọng nhất ảnh hưởng trực tiếp đến tính toàn vẹn dữ liệu và trải nghiệm của chủ sân.Nguyên nhân:Event onClick của ô lịch đang bị gom chung luồng. Nó mặc định hiểu mọi ô "không trống" (bao gồm cả lịch đặt của khách và lịch bảo trì từ DataSeeder.java) đều là lịch đặt (BOOKED), do đó bật lên Modal "Hủy lịch".  Hiện tượng "Hủy xong ô thành trống, nhưng reload lại thì vẫn là bảo trì" xảy ra do Frontend đang dùng Optimistic Update (tự động cập nhật UI trước khi gọi API). Khi bạn bấm Hủy, UI ép ô đó thành trống, nhưng API gọi xuống Backend bị tịt (vì bản chất đó là record khóa sân LockLog, không phải Booking để hủy). API báo lỗi ngầm, nhưng UI không catch lỗi để render lại (rollback), dẫn đến sai lệch dữ liệu.Cách fix:Tách bạch Enum: Tại onClick của SlotCell, bạn bắt buộc phải kiểm tra chính xác thuộc tính trạng thái (slot.status).status === 'AVAILABLE': Mở luồng tạo lịch đặt mới.status === 'BOOKED': Mở Modal Chi tiết/Hủy booking.status === 'LOCKED' / 'MAINTENANCE': Mở Modal hiển thị thông tin Bảo trì. Tuyệt đối không hiện nút Hủy lịch.Sửa lỗi UI Ảo: Tạm thời tắt Optimistic Update cho các thao tác nhạy cảm. Chỉ cập nhật lại dữ liệu của ma trận thông qua việc refetch API hoặc update state sau khi nhận được response 200 OK từ Backend.4.
